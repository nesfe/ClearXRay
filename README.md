`ClearXRay` фиксирует воспроизводимую рабочую конфигурацию `Xray REALITY` и документирует причину отказа конфигурации с `flow=xtls-rprx-vision`, которая ранее использовалась на рабочем сервере.

Основная задача репозитория:

- дать минимальную рабочую конфигурацию `VLESS + REALITY`;
- сохранить техническое описание установленной причины отказа;
- предоставить единый скрипт развёртывания по образцу простых bootstrap-репозиториев;
- исключить из базовой установки параметры, которые верифицированно переводят конфигурацию в нерабочее состояние.

## Установленный результат

Причина отказа была проверена на одном и том же сервере методом A/B-сравнения.

Рабочий вариант:

- `VLESS + REALITY`
- `network=raw`
- `type=tcp`
- без параметра `flow`
- один inbound на `443/tcp`

Нерабочий вариант:

- тот же сервер;
- тот же клиент;
- тот же `UUID`;
- тот же `pbk`;
- тот же `shortId`;
- тот же `SNI`;
- единственное существенное отличие: `flow=xtls-rprx-vision`

Результат проверки:

- конфигурация без `flow` устанавливает рабочую сессию и пропускает трафик;
- конфигурация с `flow=xtls-rprx-vision` не устанавливает рабочую сессию.

Для данного сервера, клиента и маршрута это означает следующее:

> Воспроизводимо работает базовая конфигурация `VLESS + REALITY` без `flow`.  
> Добавление `flow=xtls-rprx-vision` переводит соединение в нерабочее состояние.

## Рекомендуемая конфигурация

Для базового развёртывания рекомендуется использовать следующую схему:

- один inbound;
- один публичный порт: `443/tcp`;
- `security: reality`;
- `network: raw`;
- единый hostname в `target`, `serverNames` и клиентском `sni`;
- отсутствие параметра `flow` в серверной и клиентской конфигурации.

Типовой вид клиентской ссылки:

```text
vless://UUID@SERVER_IP:443?encryption=none&type=tcp&security=reality&sni=www.mix.com&fp=chrome&pbk=PUBLIC_KEY&sid=SHORT_ID#clearxray
```

Ключевые свойства этого профиля:

- `type=tcp`;
- `security=reality`;
- `sni` совпадает с серверным `serverNames`;
- параметр `flow` отсутствует.

Дополнительно установщик может развернуть экспериментальный профиль `VLESS + REALITY + flow=xtls-rprx-vision` на отдельном порту. Этот профиль создаётся отдельным inbound, отдельным `UUID`, отдельной парой ключей и отдельным `shortId`, чтобы его можно было тестировать независимо от базовой рабочей конфигурации на `443/tcp`.

## Установка одной командой

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/nesfe/ClearXRay/main/install.sh)
```

Установщик рассчитан на `Ubuntu 22.04+` и выполняет полную пересборку серверной части с очисткой ранее установленного VPN-стека.

## Что делает установщик

Сценарий установки:

1. удаляет остатки предыдущих установок `Xray`, `Amnezia`, `Outline` и `Docker`;
2. очищает правила `iptables`, останавливает конфликтующие сервисы и освобождает `443/tcp`;
3. устанавливает зависимости и `Xray-core`;
4. генерирует новый `UUID`, пару `x25519` и `shortId`;
5. записывает минимальную конфигурацию `REALITY` без `flow`;
6. проверяет конфигурацию через встроенный тест `xray`;
7. настраивает `ufw` с открытыми портами `22/tcp` и `443/tcp`;
8. запускает сервис и проверяет наличие слушающего сокета;
9. формирует готовую `vless://` ссылку и QR-код для импорта в клиент;
10. при выборе Vision-опции формирует отдельную ссылку и QR-код с `flow=xtls-rprx-vision` на выбранном порту.

После установки на сервере создаются:

- `/usr/local/etc/xray/config.json`
- `/root/clearxray.env`
- `/root/clearxray-link.txt`
- `/root/clearxray-qr.png`

Если включён экспериментальный Vision-профиль, дополнительно создаются:

- `/root/clearxray-vision-link.txt`
- `/root/clearxray-vision-qr.png`

## Параметры клиентского профиля

Назначение основных параметров:

- `UUID` — идентификатор клиента в `VLESS`;
- `pbk` — публичный ключ `REALITY`, соответствующий серверному приватному ключу;
- `sid` — `shortId`, используемый сервером для проверки клиента;
- `sni` — имя хоста, которое клиент передаёт в TLS/REALITY-рукопожатии;
- `fp` — отпечаток TLS-клиента, например `chrome`;
- `flow` — параметр режима передачи `VLESS`; в данном репозитории намеренно не используется.

Если нужен подробный разбор параметров и последовательности рукопожатия, см.:
